# Optional Open Library discovery

Ticket 06 implements Open Library only. This capability is disabled by default and is not required for the hosted showcase. Code/static review is complete; upstream behavior, persistence, migration execution, model behavior and account isolation remain for user QA.

## Enable deliberately

1. Review and apply `supabase/migrations/20261005060400_optional_open_library.sql` after the existing migrations through the [first-library workflow](05-first-library.md#4-link-review-and-apply-the-migration). It has been authored, not applied. The migration adds nullable, insert-only `catalog_metadata` and admits `search_catalog` in persisted safe activity. Existing owner RLS, column grants, mutation versions and durable operation coordination are preserved.
2. Set `OPEN_LIBRARY_ENABLED=true` and `OPEN_LIBRARY_CONTACT_EMAIL` to your actual contact email in server environment configuration, then restart the app. The contact is sent only to Open Library in the identifying User-Agent. Invalid/missing contact configuration produces an honest unavailable result. Leaving the enable flag absent or false hides discovery and removes its MCP tool; ordinary library/import/chat paths make no catalog calls and work without this migration.
3. Open **Add a book → Find an edition with Open Library**, or `/library/catalog`. Enter a title/query or ISBN and optional author. Results are labeled external Open Library works; none are inserted automatically.
4. Select **Review suggested edition**, inspect edition ID, ISBN, publisher/date and language, then save the normal book form. Titles/authors/pages can be corrected; ownership, status, rating and notes are reader inputs. Unknown authors require manual entry. Description is plain text hidden behind a spoiler disclosure. Covers are optional returned metadata; the UI does not require or load them.

No dependencies, accounts, deployments, background jobs or paid API requests were added. The setup instructions do not provision resources or apply migrations.

## Contracts and boundaries

`src/books/catalog/provider.ts` exposes `searchBooks` and `getBookDetails`; shared app-owned schemas distinguish work results from precise edition metadata. Search uses `/search.json` with explicit fields and at most 10 results (UI limit 5), returning work identity/title/authors/source URL and the suggested edition ID. Work results deliberately contain no ISBN/page count. The selected edition uses `/books/<edition ID>.json`, and bounded author lookups resolve its authors. ISBN, pages, cover, description, language, publication date and publishers come only from that edition where available. No work-level median pages, invented descriptions or taste/difficulty scores are used.

Requests have a seven-second timeout and a 512 KiB decompressed-response bound; edition lookup has a total 15-second deadline. A five-minute, 100-entry process-local cache holds public upstream JSON only. A process-local admission gate spaces upstream requests by at least 1.1 seconds; competing requests fail honestly rather than queueing without bound. HTTP 429 imposes a one-minute local cooldown. There are no automatic read or write retries. These bounds are per running process, not a distributed quota; this is intended for the controlled low-volume showcase, not bulk catalog ingestion.

Authenticated MCP discovery advertises `search_catalog` only when enabled. It accepts `{query, author?, isbn?, limit?}`; limit defaults to 5 and is restricted to 1–10. Query is 1–200 characters, optional ISBN is unhyphenated ISBN-10 or ISBN-13. Results are `{ok:true,candidates}` or `{ok:false,error:{code,message}}`, with `VALIDATION_ERROR` or `UPSTREAM_UNAVAILABLE`. Public catalog content does not bypass bearer authentication. The registry marks the tool read-only and open-world; activity stores only its name/phase/outcome. The initial ticket restricted chat to explicit external discovery and saved-library recommendation cards; the expanded tools now permit history-based external recommendations and display labeled catalog cards. This describes ticket 06 alone. The [expanded tool migration](12-expanded-agent-tools.md) adds edition reading/addition in chat, history-based external recommendation cards and optional internet search; those contracts supersede the initial read-only chat limitation.

Saving calls the existing `createBook` service with the verified reader and a server-captured edition snapshot. The page Server Action encrypts its closure; form inputs cannot supply catalog provenance or ISBN. A stable book UUID and the same frozen edition snapshot are reused after failed submissions; duplicate-ID recovery compares both normal fields and normalized provenance/ISBN. No catalog request runs during save, so an upstream outage does not discard an already reviewed draft. The authoritative saved book displays its Open Library provenance link. Catalog metadata is separate from personal fields and is insert-only; catalog actions do not modify existing books. Existing editing remains version checked and leaves provenance intact. Metadata fill/replacement and automatic duplicate merging are not implemented; the ticket's deliberate-add path fulfills the add-or-fill acceptance criterion. Review your library before adding a potentially duplicate edition.

## User verification

- Enable/disable discovery and confirm tool discovery follows configuration; manual add, import and saved-library recommendations remain available with it disabled or unavailable.
- Search title/author/ISBN, no-match, validation, timeout, malformed response, rate-limit and missing-contact states. Inspect suggested-edition identity and edition-only page counts/ISBNs. Check keyboard use, pending states and spoiler disclosure.
- Save with missing authors/pages and corrected personal inputs; reload and inspect provenance. Retry the same failed/uncertain save without changing its UUID/details; verify persisted metadata remains the reviewed snapshot. Verify ordinary book edits and Goodreads reimport preserve existing values.
- Exercise explicit external discovery through real MCP HTTP/chat, ordinary saved-library recommendations, safe persisted activity and refresh. Model adherence to explicit-request rules remains unverified.
- Verify anonymous rejection and two real readers through UI/MCP/Data API. Review insert-only metadata grants and unchanged version/retry behavior. Functional tests, browser QA and builds belong to the user.

## Official references

Checked the [Open Library Search API](https://openlibrary.org/dev/docs/api/search), [edition REST and field documentation](https://openlibrary.org/dev/docs/api/books) and [usage/rate limits](https://openlibrary.org/developers/api). The documented unidentified limit is one request/second; this app stays below it even with an identifying contact. No provider SDK was introduced. Existing [Supabase insert/RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Next.js Form](https://nextjs.org/docs/app/api-reference/components/form) and [Server Action closure](https://github.com/vercel/next.js/blob/canary/docs/01-app/02-guides/data-security.mdx) APIs were retained or checked against official documentation; installed SDK versions were unchanged.
