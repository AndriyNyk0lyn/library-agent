## Implementation decisions

- Use the OpenAI Agents SDK for TypeScript with the configured server-only key and exact `OPENAI_MODEL`. Verify current APIs/dependencies in official docs. Author project-specific instructions; use one agent and a fresh authenticated MCP client per run. Forward the reader's valid token to the configured endpoint, close resources, and never substitute direct book-service calls for MCP.
- Add a user-owned reader profile with explicit preferences, optional positive pages/hour and daily reading minutes, and user-confirmed timezone for date-sensitive actions. Provide a simple profile editor. Add `get_reader_profile` and `update_reader_profile` tools, reusing the profile service. Update preferences only when explicitly requested/confirmed; a reaction or temporary prompt does not silently become lasting memory. Make profile writes versioned and retry-safe using the established operation mechanism.
- Agent capabilities: search/resolve books, read details and reactions, perform explicit status/rating/note/date updates, compare candidates, recommend up to three eligible want-to-read books, and explain uncertainty. Owned-only requires known ownership. Fewer eligible candidates means fewer recommendations. Ambiguous titles require clarification before mutation. Explicit 8/10 means 4/5; unsupported half-star conversions require clarification. Never invent finish dates; "today" uses the reader's confirmed timezone.
- Persist user-scoped display messages, safe tool activity, and run outcomes. Choose one continuation approach: bounded SDK-compatible history stored in Supabase and restored server-side. Include the tool-call/result history needed by the installed SDK, not just visible prose. Keep display and continuation representations separate when required, validate persisted records, and document the bounded retention policy. Do not mix response-ID and manual-history continuation strategies.
- Use assistant-ui with its custom/external-store runtime adapter to render the existing application-owned messages/events. Keep Supabase as the source of truth; no assistant-ui cloud service or second agent runtime. Use shadcn/ui for shared controls. Present structured book links/cards and safe tool summaries, not raw private payloads or reasoning.
- Stream fetch-readable SSE with run IDs and events run_started, tool_started, tool_completed, message_delta, run_completed, run_failed. Include only necessary validated fields. After disconnect, reload persisted status/messages and show completed/failed/interrupted or uncertain state; never automatically resubmit a turn or mutation. Expired active runs must recover rather than remain permanently locked.
- Bound input to 4,000 characters, model turns to 8, runs to 10/user/hour, and one active run/user. Persist quota/concurrency coordination with expiry in PostgreSQL so it works across instances. Configure cancellable upstream/tool calls and total deadline below hosting duration, leaving time for final persistence. Cancellation may leave uncertain writes; report them honestly.
- Disable sensitive provider tracing or tracing entirely until safe configuration is established. Treat notes, imported reviews, and catalog text as data. Keep secrets out of client code, tool summaries, errors, and logs.

## Acceptance criteria

- [x] Chat reads and updates actual library records through authenticated MCP HTTP using the current reader's token.
- [x] Recommendations contain only eligible saved books with real IDs, brief reasons/trade-offs, and honest uncertainty.
- [x] Explicit profile preferences and reading constraints persist and influence later turns; temporary wishes remain temporary.
- [x] Refresh restores conversation and tool-compatible continuation, with user-owned storage and bounded history.
- [x] assistant-ui renders messages, composer, progress, structured results, and actionable errors through the custom backend adapter.
- [x] Persisted run limits, deadlines, disconnect recovery, and safe activity are implemented without automatic write replay.
- [x] Plan/catalog capabilities are not claimed before their tickets implement them.
